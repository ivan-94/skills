# Agent Context Audit

这个 skill 用来检查“一个新 agent 在当前上下文引导下，会怎么理解和行动”。sub-agent 是答题者，先回答场景题，再被追问探索账单；主 agent 是考官，先收卷，再自己读取项目文件建立标准答案，最后评卷和诊断上下文问题。

## 核心模型

- 必须能 fork 或启动独立 sub-agent。不能 fork 时，直接说明当前环境无法执行本审计。
- sub-agent 必须是干净新会话：不继承父对话历史、前文结论、当前 skill 设计讨论、主 agent 的探索结果或评分思路；工具做不到时，停止答题审计并说明污染风险。
- 主 agent 负责出题、分两阶段发卷、收卷、探索标准答案、评卷和写诊断报告。
- sub-agent 只负责答题。不要让 sub-agent 评分、诊断项目文档质量、提出修复方案，或知道主 agent 的评分标准。
- 本 skill 只诊断和建议，不修改文件、不执行项目命令。
- 报告语言跟随用户；用户未指定时使用中文。

## 出题

用户可以直接给一个或多个场景问题。每个问题独立 fork 一个 sub-agent 作答，不要把其他题目、参考答案、主 agent 猜测、评分标准或探索账单要求混进第一阶段问题里。

如果用户不知道怎么出题，先给参考题供用户选择或改写，不要默认全部执行：

- “如何将这个项目从空白环境跑起来？如果有多种方式你会怎么选择？怎么跑单元测试，遵循什么约定？”
- “现在你完成了一个功能，你如何跑 HAT（Hand Acceptance Test）？”
- “如果要开发一个新功能，你推荐走什么流程？请详细描述。”
- “如果要修复一个线上 bug，你会如何定位、验证和交付？”

## 上下文探针

上下文探针是内置题目，不是默认必跑项。只有用户明确要求检查上下文、执行上下文探针、审计默认加载内容或类似意图时才执行；如果用户只给场景题，就只发场景题。它不回答场景题，不使用工具，不读取文件，只复述新会话自然加载到的上下文。

```text
你是“上下文探针”。禁止使用任何工具、命令或文件读取。只根据当前已加载到会话里的上下文回答。

输出：
1. 你看到的上下文来源位置：只列显式可见的文件路径、URL、系统/开发者/用户说明；无法确认路径时写“未显式可见”。
2. 当前会话规则摘要：用 5-10 条说明你认为最会影响后续行为的规则。
3. 干扰因素：哪些规则可能过宽、过旧、与任务无关或会误导 agent。
4. 矛盾或张力：列出互相冲突、优先级不清或容易被误解的指令。
5. 不确定项：哪些关键信息无法从默认上下文确认。

每条判断标注置信度：高/中/低。不要根据仓库内容猜测；没有证据就写不确定。
```

## 答题者两阶段 Prompt

除上下文探针外，所有 sub-agent 都按两阶段作答。第一阶段只收到问题；第二阶段在它回答完之后，主 agent 再追问探索账单。`{问题}` 必须是用户给出的场景题，或用户从参考题中确认过的题。

第一阶段：

```text
{问题}
```

第二阶段：

```text
请补充本题的探索账单。只描述你为了回答上一题实际读取或查看过的信息：

1. 读取或查看了多少个文件、文档、上下文片段或工具结果。
2. 关键路径或来源是什么。
3. 你为什么读取这些来源，它们分别帮助你确认了什么。
4. 哪些结论是文件证据支持的，哪些仍是推断。

不要评价答案是否正确，不要诊断项目文档质量，不要提出修复建议。
```

答题者只能陈述答案、客观事实、依据和自己的思路。探索账单只记录它读了什么、为什么读、证据和推断边界；不要要求它判断答案是否正确、项目文档是否合格，或应该如何修复。

## 考官流程

1. 根据用户指令决定执行上下文探针、场景题，或两者都执行。
2. 每道场景题独立 fork 一个答题者，第一阶段只发送 `{问题}`。
3. 答题者回答后，向同一个 sub-agent 发送第二阶段探索账单 prompt。
4. 收集所有答卷和探索账单。若某个答题者失败或超时，保留失败信息。
5. 主 agent 自己只读项目文件和可见工作流文档，建立标准答案。允许读取文件和搜索；禁止修改文件、执行项目命令或创建产物。
6. 评卷：比较答题者答案与标准答案，判断答案是否正确、思路是否合理、读取路径是否暴露上下文引导问题。
7. 输出诊断报告，只给建议，不自动修复。

## 评卷维度

- **答案正确性**：答题者给出的命令、流程、入口、优先级或判断是否符合项目事实。
- **思路正确性**：答题者是否先找合适入口、是否区分证据和推断、是否避免臆造。
- **探索成本**：读取文件数量、关键路径是否集中、是否因为入口分散或说明冲突导致探索扩大。
- **上下文污染**：默认上下文是否让答题者误解任务、权限、流程、命令或 HAT 边界。
- **改进建议**：由主 agent 提出应补充、删除或改写哪些上下文入口。

探索成本用软阈值判断：读少量入口文件即可答对是低；需要追到多个目录或配置是中；需要反复搜索、读取大量散落文件或仍答不准是高。不要用固定文件数硬判。

## 汇总报告

最终报告推荐结构：

- **执行状态**：用户要求的上下文探针和各场景题是否完成。
- **总体现状**：一句话说明新 agent 的认知是否可靠。
- **答卷评审**：逐题列出答题者答案、标准答案摘要、正确性、思路评价和探索成本。
- **上下文来源与冲突**：汇总默认上下文里的显式来源、干扰因素和矛盾。
- **高风险问题**：会导致 agent 做错事、走错流程或误判验收的点。
- **改进建议**：建议修改哪些 AGENTS/CLAUDE/README/HAT/工作流入口，以及要补什么信息。
