主要目标： 对用户指定的 SKILLS 进行深度审查。

审查这的角色：你是一个 Agent，作为 Skills 的使用者或者用户，需要从你自己角度来分析这个 Skills 是否对你有用, 并且你知道什么时候应该用它， 什么时候不应该用， Skills 应该给你传达正确、清晰、简洁、没有歧义的信息。严苛地挑出所有毛病。

审查范围：SKILL.md 以及它引用的所有文件.

审查的角度：
- 是否存在矛盾、歧义、不一致。比如:
  + 前后矛盾的描述
  + 一件事情存在多种描述、多种路径， 却没有决策的指导。
  + 实现和文档不一致。比如 SKILL.md 和 references 不一致，或者 scripts 的实现和稳定不一致。
  + 等等。只要你感觉到任何困惑，这个 Skills 就有问题
- 清晰度。 比如：
  + 描述和目标是否清晰、准确、完整。
  + 执行路径是否清晰、明确、无歧义、 无隐藏路径。
  + references 文档是否完整、覆盖所有 scripts 的用户接口/AUI.
  + Skills 的输入输出是否明确
- 简洁性。比如:
  + 是否存在冗余、重复、不必要的信息。
  + 是否暴露的技术的实现细节。SKILL 和 references 描述的是面向 Agent 的接口(AUI), 而不是实现细节。
  + 是否存在一些 Agent 显而易见的东西。比如你非常熟知的知识
  + 是否包含了一些自动化流程里面的东西，比如 CLI 内部已经实现了，不需要披露出来。
  + 总之，当你识别到对实现当前任务无关的、没有帮助的、重复的描述时，就应该指出来。
- 完整性。比如：
  + references 文档是否完整、覆盖所有 scripts 的用户接口/AUI.
  + 工作流是否完整、没有遗漏。
  + 是否存在未定义的区域和内容
- 引导性。比如:
  + 引导是否太弱，哪些信号应该增强，可以让 Agent 更好地完成任务、避免偏移。
  + 哪些是错误的引导，可能会让 Agent 偏离任务。
  + 哪些流程环节可以增强
- 易用性。比如：
  + 是否方便用户去执行，有些涉及到需要用户参与的流程。需要用户参与的点是否明确，没有隐藏。
- 合法性。SKILLS 的结构是否合法，符合规范
- 结构性。结构是否可以进一步优化和整理。
